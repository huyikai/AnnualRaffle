# 年会抽奖系统

年会现场抽奖工具。3D 标签云 + 多奖项配置 + 人员名单管理与照片头像，
支持 **Windows / macOS 桌面客户端**与网页版并行使用，数据全部保存在本机。

## 桌面客户端（Windows / macOS）

基于 **Tauri v2**，安装包约 15 MB，启动快、内存占用低，**不依赖网络**。

### 下载安装

到 [Releases 页面](https://github.com/huyikai/AnnualRaffle/releases) 下载对应系统的安装包。

> **未签名版本说明**
>
> 安装包未做代码签名，首次打开会被系统拦截——这是预期行为，不是安装失败：
>
> - **macOS**：提示「无法验证开发者」→ **右键点击应用 → 打开** → 再点「打开」
>   或在终端执行 `xattr -dr com.apple.quarantine /Applications/年会抽奖.app`
> - **Windows**：SmartScreen 蓝窗 → 点「**更多信息**」→「**仍要运行**」
>
> 部分杀毒软件可能误报，请选择「信任」或加入白名单。

> **Release 是草稿？**
>
> 工作流配置为 `releaseDraft: true`，构建完成后 Release 停在草稿状态，
> 需维护者手动点 Publish。若 Releases 页面看不到安装包，说明还没发布。

### 功能

| 分类 | 能力 |
|---|---|
| **人员管理** | CSV 上传 / 批量粘贴 / 单人增删改 / 批量启停 / 工号与姓名搜索 |
| **照片头像** | 按工号自动匹配、导入时校验格式并压缩、孤儿照片清理 |
| **背景** | 12 张预设 + 自定义上传，三档适配（铺满 / 完整 / 拉伸） |
| **音频** | 自定义 BGM 与抽奖音效，音量分轨控制，各带试听 |
| **现场** | 全屏演示模式（F11 进出）隐藏全部操作入口，大屏字号自适应 |
| **结果** | 分奖项查看、点击删除中奖记录、导出 CSV |
| **数据** | JSON 导入导出 + 自动快照滚动保留最近 10 份 |

### 系统要求

- **macOS** 11 或更高
- **Windows** 10 或更高（依赖 Edge WebView2 Runtime，Win11 与常规 Win10 已内置）

## 快速上手

首次使用四步：

1. **导入名单** — 「人员管理 → 批量导入」，粘贴或上传 CSV（仅需「工号,姓名」两列）
2. **导入照片**（可选）— 「人员管理 → 导入照片」，选择照片文件夹，按文件名自动匹配
3. **挑背景和音乐**（可选）— 「设置 → 背景 / 音频」
4. **开抽** — 回到首页选奖项，点「开始抽奖」→「停止」

> 名单为空时，抽奖页与人员管理页都会显示引导入口，点一下就能开始导入。

## 使用指南

### 导入名单

**CSV 文件**：支持 UTF-8 与 GBK 编码，自动识别表头（`工号`/`编号`/`员工号` 或 `id`/`no`/`number`）与分隔符（制表符、逗号、中文逗号、分号），也可以直接把文件拖进对话框。

**批量粘贴**：从 Excel / WPS / 飞书表格整块复制后粘贴，分隔符自动识别。

**导入前会先预检**，逐行标出：

| 情况 | 处理 |
|---|---|
| 工号为空 | 该行异常，不导入 |
| 姓名为空 | 该行异常，不导入 |
| 工号在文件内重复 | 标出与第几行重复 |
| 工号已存在于当前名单 | 标为「冲突」，可选跳过 / 覆盖 / 新增 |

预检表会**同时显示「原始值 → 归一化值」**，方便肉眼核对。归一化会做这些事：

- 去掉首尾空格与全角空格
- 全角数字转半角（`２２０００３０` → `2200030`）
- 去掉零宽字符与 BOM
- **保留前导零**（`0012345` 不会被吃掉）
- 保留字母前缀（`E00123` 不会变成 NaN）
- 形如 `2.20003E+15` 的科学计数法**判为损坏数据**并拒绝——这是 Excel 导出时就已经损坏的，无法还原

**覆盖策略会重置参与开关与奖项限制**，因为导入只带工号+姓名，沿用旧值会造成误解。

### 配置奖项

- 每个奖项可设置中奖人数
- 可**改名、可删除**，内置的五个奖项删了也能「一键恢复」
- 每个奖项可选「跟随全局」或「自定义」排除规则
- 预设名单：指定某奖项的中奖人；人数不足时自动补抽，补抽同样遵循排除规则
- 奖项增删后，人员身上指向已删除奖项的参与限制会标记为「已失效」并可一键清理

### 现场操作

| 操作 | 快捷键 / 位置 |
|---|---|
| 进入演示模式 | `F11` 或首页「演示模式」按钮 |
| 退出演示模式 | `Esc` 或 `F11` |
| 开始 / 停止抽奖 | 首页底部按钮 |

演示模式会隐藏**全部操作入口**（人员管理、设置、重置等）并隐藏鼠标指针——
投屏时这些按钮全暴露在观众视野里，「重置」还常驻右下角，误触代价是整场活动数据清空。

结果卡字号按**视口宽度 × 人数**双因子计算，1280 到 4K 投影都清晰。

### 导出结果

「抽奖结果」弹窗右上角 → 导出 CSV → 选「导出全部奖项」或只导出某一个。

文件带 **UTF-8 BOM**，Excel 和 WPS 双击打开都不乱码。姓名口径与页面显示一致。

## 照片命名规则（重要）

照片按**文件名**匹配工号，优先级如下：

| 优先级 | 文件名格式 | 说明 |
|---|---|---|
| 1 | `10001.jpg` | 最可靠 |
| 2 | `10001-张三.jpg` | HR 系统导出常见 |
| 3 | `张三.jpg` | **仅当姓名在名册中唯一** |

**同名时不猜**：名册里有两位「赵六」时，`赵六.jpg` 会被判为歧义并明确报错——
猜错就是把别人的脸挂到别人头上，而且不会有任何提示。

导入时按四道校验逐层拦截：

1. 扩展名白名单（jpg / jpeg / png / webp）
2. **文件头嗅探**——把 `.exe` 改名成 `.jpg` 会被识破
3. 大小上限 10 MB
4. 浏览器实际解码——截断的、伪造的文件在这里被拦下

通过校验后统一压缩为 **最长边 512px 的 JPEG**（实测 1100 KB → 24 KB），存到应用数据目录。

> **孤儿照片**：照片先到、名单后导入时，多余照片会被保留；名单导入后自动匹配上。
> 「人员管理 → 清理无用照片」可以删掉名册中已不存在的那些。

## 数据与备份

### 存放位置

| 平台 | 路径 |
|---|---|
| macOS | `~/Library/Application Support/com.annualraffle.desktop/` |
| Windows | `%APPDATA%\com.annualraffle.desktop\` |

目录结构：

```
com.annualraffle.desktop/
├── avatars/        照片头像（{工号}.jpg）
├── backgrounds/    自定义背景
├── audio/          自定义音乐与音效
└── backups/        自动快照（滚动保留最近 10 份）
```

**名单、奖项配置、中奖结果**存在应用数据目录下的 WebView 存储中，不落图片文件。

### 备份与恢复

「设置 → 关于 → 数据备份」：

- **导出备份文件** — 选路径存一份 JSON
- **创建本地快照** — 立即在 `backups/` 落一份，不等 3 秒防抖
- **从备份恢复** — 选择 JSON 覆盖当前数据

每次修改名单后会自动滚动写快照。**崩溃或误操作后，这是唯一能救命的兜底**——
名单可以重新导入，**中奖记录救不回来**。

### 应急操作卡

年会当天印一页贴在现场电脑上：

| 问题 | 怎么办 |
|---|---|
| macOS 打不开 | 右键 → 打开；或 `xattr -dr com.apple.quarantine /Applications/年会抽奖.app` |
| Windows 被拦截 | 「更多信息」→「仍要运行」；或用 `.msi` 版本 |
| 误点「重置全部」 | 设置 → 关于 → 打开 `backups/` 目录，取最新的 JSON 恢复 |
| 换机器 | 旧机器「导出备份文件」→ 新机器「从备份恢复」→ 重导照片 |
| 应用完全装不上 | 用 [网页版](https://huyikai.github.io/AnnualRaffle/) 临时顶上 |

## 网页版

与桌面端并行，访问 <https://huyikai.github.io/AnnualRaffle/>。

**功能差异**：

| | 网页版 | 桌面端 |
|---|---|---|
| 抽奖、奖项配置、名单管理 | ✅ | ✅ |
| 中奖结果导出 CSV | ✅ | ✅ |

网页版定位是**桌面端装不上时的临时备选**，功能基本等价。

## 从源码构建

```bash
git clone https://github.com/huyikai/AnnualRaffle.git
cd AnnualRaffle
pnpm install

pnpm dev            # 网页版开发（http://localhost:5188）
pnpm tauri:dev      # 桌面端开发
```

> **端口 5188**：默认的 5173 容易被本机其他项目占用，Vite 会静默换端口，
> 导致 e2e 打到别的应用上。已固定 5188 并启用 `strictPort`。

### 构建

```bash
pnpm build          # 网页版（base: /AnnualRaffle）
pnpm build:tauri    # 桌面版（base: ./，Tauri 从 tauri://localhost 加载必须用相对路径）
pnpm tauri:build    # 产出 .app / .dmg / .msi / .exe
```

> Windows 安装包**必须在 Windows 上构建**（NSIS/WiX 不支持跨平台交叉编译）。
> 仓库已配置 GitHub Actions，推 `v*` tag 即自动构建并创建 Release。

| 层 | 选型 |

## 开发

```bash
pnpm test:run       # 单元测试（117）
pnpm test:e2e       # 端到端（53）
pnpm lint           # 代码风格（自动修）
pnpm lint:check    # 代码风格（只检查，CI 用）
```

### CI

`.github/workflows/` 下三个工作流：

| 工作流 | 触发 | 内容 |
|---|---|---|
| `ci.yml` | push / PR | lint + 类型 + 单测 + 双模式构建路径断言 + e2e |
| `deploy.yml` | push main | 部署网页版到 GitHub Pages |
| `release.yml` | tag `v*` | 构建 macOS universal + Windows，上传 Release |

`release.yml` 在打 tag 前会校验四处版本号一致（`package.json`、`tauri.conf.json`、`Cargo.toml`、`release.ts`）。

### 开发模式下的桌面自检

`pnpm tauri:dev` 会在启动时跑一遍全链路自检（造图 → 校验 → 压缩 → 写盘 → 资产协议读回 → 枚举清理 → 背景写入 → 快照），
结果写到应用数据目录的 `selfcheck.json`，便于确认原生侧是否通畅。仅开发模式运行，生产构建中被静态消除。

## 已知限制

- **安装包未签名**，首次打开需按上文步骤绕过系统拦截
- **网页版不能导入照片、上传背景与音乐**（浏览器无文件系统写入）
- **无法自动更新**（无签名不能用 Tauri 内置 updater），需手动下载新版替换
- **照片只能存在桌面端**；网页版沿用 `public/user/` 约定，运行时只读
- **无局域网协同**：不支持一台机器配置、另一台投影
- 奖品图片与奖品描述等富信息**未实现**
